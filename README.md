# Sales Buddy｜端到端 AI 销售作战系统

Sales Buddy 不是一个单独的 CRM 页面，而是一套从“找到客户”到“推进成交、沉淀复盘”的端到端销售产品。

用户只需要提出一句业务目标，例如：

> 帮我找一批适合腾讯云的 AI 视频行业客户。

WorkBuddy 中的 Sales Buddy 专家会编排获客与调研 Skill，生成可核验、可导入的客户数据；CRM Web App 接住研究结果，继续完成客户分级、跟进、关系管理、会议准备、机会诊断、成交协同和全景报告输出。

## 产品全流程

```text
一句话销售目标
    ↓
Sales Buddy 专家（WorkBuddy 内的任务理解与流程编排）
    ↓
商机雷达 enterprise-prospect-research
发现、筛选并核验一批目标客户
    ↓
客户透镜 enterprise-customer-deep-research
对重点客户进行单客户深度研究
    ↓
CRM 原生 JSON（v1 / v2）
    ↓
Sales Buddy CRM Web App
导入 → 分级 → 推进 → 记录 → 诊断 → 协同 → 成交
    ↓
客户全景报告 / 周期销售复盘
```

本仓库包含 CRM Web App、两个 Skill 的源码与交付样例，以及三者之间使用的 CRM 数据契约。WorkBuddy 专家运行在 WorkBuddy 中，不在本仓库内。

## 三个产品组件

### 1. 商机雷达：批量找到值得跟的客户

目录：`获客Skill/enterprise-prospect-research/`

- 围绕行业、产品或客户画像发现候选企业。
- 通过多通道公开证据核验企业主体与商机信号。
- 对客户进行评分和分级，明确推荐理由、风险与下一步动作。
- 输出 CRM JSON、Markdown 清单和独立 HTML 报告三件套。
- `crm-customer-list.v2` 可携带完整账户全景情报，CRM 导入后会出现“账户全景 / 腾讯机会 / 面客准备”专属视图。

### 2. 客户透镜：把一家客户研究透

目录：`调研Skill/enterprise-customer-deep-research/`

- 锁定法定主体，避免同名企业和错误归因。
- 研究公司、业务、产品、组织、云与 AI 线索、关键事件和潜在机会。
- 区分公开事实、销售推断和仍需客户确认的问题。
- 生成可审阅 Markdown、独立 HTML 和可直接导入 CRM 的单客户 JSON。
- 深调结果以完整快照进入 CRM；再次导入同名客户时，可更新公开研究并保留销售私有数据。

### 3. CRM Web App：把研究结果变成下一步行动

Web App 的信息架构由四个主工作区组成：

- **今日**：AI 信息收件箱、优先行动、逾期待办和重点客户脉搏。
- **客户**：客户列表、筛选、分级、批量导入、多选管理和客户作战空间。
- **任务**：从每次跟进中的“下一步 + 日期”自动形成待办，可完成也可恢复。
- **分析与复盘**：按本周、上周、本月、上月汇总推进事实、风险和下周期行动。

## CRM Web App 已实现能力

### 客户接入与数据治理

- 新建客户、单条手动录入以及客户删除/批量删除。
- 支持拖拽或选择 `JSON`、`CSV`、`TSV`、`XLSX`、`XLS`。
- 导入前逐条预览、校验和勾选；同名客户可选择跳过或更新。
- 兼容 `crm-customer-list.v1` 和 `crm-customer-list.v2`，也可直接接收客户透镜生成的单客户深调包。
- 公开研究更新不会覆盖既有推进记录、已建联关系等销售私有数据。

### AI 跟进记录

- 输入会议、电话、微信等自然语言记录，也可附加材料或使用浏览器语音输入。
- AI 提取客户、联系人、沟通方式、关键信息、下一步和提醒日期。
- 提取结果先进入确认界面，销售可逐项选择后再写入客户档案。
- 服务端 AI 未配置或不可用时，本地规则仍可完成基础提取；系统不会把推断伪装成客户事实。

### 客户作战空间

- 以阶段路线管理线索、建联、会面、方案、成交和流失，并保留阶段历史。
- S/A/B/C 客户等级由销售人工控制，不由公开调研越权替代。
- 根据档案给出少量可确认的下一步建议，如会前准备、痛点确认和决策链确认。
- 六维机会诊断、业务与商业模式简报、外部信号、问题—影响—方案痛苦链。
- 客户联系人层级、汇报关系、角色、联系方式和独立建联状态。
- 市场动态、招聘信号、招投标、资质许可及其来源证据。
- 联合工作计划，可记录双方负责人、目标日期和完成状态。

### 会前、会后与成交工具

- 会前速记卡：沟通目标、现状假设、确认问题、异议准备和下一次会议钩子。
- 会后确认：结果、客户原话、已确认事项、未决问题与下一步。
- 谈判助手：目标、客户诉求、我方可交换项、红线、异议与 give-get 纪律。
- 销售资产工作室：生成、保存、复制和下载跟进邮件、会议议程、方案摘要、内部协同 Brief、谈判作战卡等文本资产。

### 任务、复盘与客户报告

- 下一步行动自动进入任务工作区，支持逾期识别、完成和恢复。
- 客户脉搏识别超过两周未更新的 S/A 重点客户，成交和流失客户不进入停滞提醒。
- 周期复盘自动计算新增客户、有效跟进、阶段推进、完成/逾期待办和成交/流失。
- 规则生成的周期总结可直接复制；AI 只润色表达，不改写事实与数字。
- 客户全景报告会按实际数据动态组织客户画像、机会判断、公开情报、关键关系、证据、会前会后、推进记录、联合计划和谈判策略。
- 当前界面提供独立、响应式、可转发的 HTML 报告导出；报告构建器同时具备 Word 文档封装能力。

## 事实、推断与权限边界

Sales Buddy 将“研究发现”和“销售确认”严格分开：

- 获客 Skill 只能写公开事实、来源、评分与待验证假设，不能伪造已沟通、已确认痛点或双方计划。
- 客户透镜给出证据化研究结论，但不把公开联系人自动标记为已建联。
- CRM 中的真实沟通、关系状态、客户确认、任务和成交推进由销售维护。
- AI 写入前需要人工确认；报告会将确认事实与推断内容分区呈现，并自动省略空章节。

## 数据契约

- `crm-customer-list.v1`：基础 CRM 客户数据，可承载获客结果和单客户深调快照。
- `crm-customer-list.v2`：在 v1 基础上增加完整账户全景情报，用于账户全景、腾讯机会和面客准备视图。
- `company-deep-research.v1`：客户透镜内部的深度研究快照结构。

Schema 位于 `docs/integration/`，获客与调研 Skill 内也保存了对应引用版本。导入模块会校验版本、字段、来源元数据、主体一致性以及禁止越权写入的销售私有字段。

## 运行方式

需要 Node.js 22 或更高版本。

```bash
cp .env.example .env
# 至少将 AUTH_SECRET 改成高强度随机值
npm start
```

打开 `http://127.0.0.1:3000`，注册后即可使用。Node 服务提供账号认证、按用户隔离的客户数据存储、revision 乐观锁和 AI 代理，默认数据目录为 `.data/`。

可选 AI 配置：

```bash
AI_API_URL=https://api.openai.com/v1
AI_API_KEY=your-api-key
AI_MODEL=your-model
```

`AI_API_URL` 可填写 OpenAI 兼容 API 根路径或完整的 `/chat/completions` 地址。密钥仅保存在服务端，不下发浏览器。

仓库还保留 CloudBase 登录和同步适配：配置 `cloudbase-config.js` 中的环境后可启用云端模式；未配置时使用 Node 同源 API，纯静态打开则作为本地演示模式。

## 适合如何演示

建议不要从“这是一个 CRM”开始，而是演示一条完整任务：

1. 在 WorkBuddy 中说“帮我找一批 XX 行业客户”。
2. 用商机雷达生成潜客清单和 CRM JSON。
3. 对其中一家调用客户透镜，形成单客户证据化研究。
4. 把 JSON 导入 CRM，查看账户全景、腾讯机会和面客准备。
5. 用自然语言记录一次客户沟通，确认 AI 提取结果并生成待办。
6. 完善决策链、痛点、联合计划和谈判策略。
7. 导出客户全景 HTML 报告，或在分析页生成周期销售复盘。

这条链路体现的不是“做了一个页面”，而是把获客、研究、客户推进和报告交付统一成一个可运行的销售工作流。
